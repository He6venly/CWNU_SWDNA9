## 개발 시사점 — 팀의 설계 선택

아래는 OT 의무사항이 아닌 개발 방향 제안.

- 핵심 사용자 1종과 문제 1개를 정하고, 입력→처리→결과 흐름 1개부터 완성
- 기능 수보다 실제로 끝까지 작동하는 시연 경로 우선
- 꾸럼e에 문제 정의, 대안 검토, 역할 분담, 수정 이유, 검증 결과를 실제 작업과 함께 기록
- 발표는 문제·대상 사용자 → 기존 방법의 한계 → 핵심 시연 → 차별점·검증·한계 순서로 구성
- 영상·캡처본을 준비해 현장 네트워크 문제에 대비

## 아직 확정되지 않은 사항

- 사용자 요청상 웹앱 주제 미정
- 대상 사용자, 핵심 기능, 팀 내 역할, 실제 데이터 확보 방법
- AI 기능 필수 여부: OT 텍스트에는 AI API 사용을 의무로 한다는 명시 없음
- 서버·DB·로그인·외부 API·예산
- 세부 제출 경로, 파일명 규칙, 정확한 제출 마감, 현장 추가 지침

추가 사용자 요구: Netlify 배포 필수. OT 자료에서 확인된 조건과 구분하며, 현재 구성은 해당 요구에 맞춰 설정. 실제 배포는 미수행.

참가자 명단·연락처·현장 인증정보는 개발에 불필요하므로 이 문서에 옮기지 않음.

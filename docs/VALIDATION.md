## 교차검증 방식

- 정적 타입만으로 성공 처리하지 않고 실제 Request/Response 핸들러 테스트와 공용 클라이언트의 로컬 HTTP 호출 대조
- fixture는 실제 판정 결과를 복사해 기대값으로 만드는 방식이 아닌 별도 디자인 시나리오. 실제 API 스텁의 전부 NEEDS_INFO와 구분
- 브라우저에서 입력 변경·응답·모바일 폭·결과 만료를 확인. UI 검증을 빌드 성공으로 대체하지 않는 방식
- Gemini 테스트는 주입한 모의 fetch만 사용. 실제 호출 성공으로 보고하지 않음

## 남은 확인 사항

- 실제 GEMINI_MODEL 호환성, Gemini 검색 grounding의 실제 응답·출처·제품 식별 정확도, 판독 불가 사진의 null 처리
- 공식 항공사 규정 확보·검수·갱신과 Gemini 대조 결과의 정확성. 현재는 실제 규정 수치 없음
- Gemini 라우터 연결 전 공개 API 요청 제한·사용자 식별 필요성·제공자 지출 제한·외부 사진 전송/보관 정책 확정
- 실제 카메라·대용량/고해상도 사진·회전/EXIF·HEIC·메모리 사용·느린 네트워크·사용자 연속 조작의 기기별 확인
- 체크 화면은 디코딩 후 화소 상한을 확인하므로, 매우 큰 압축 이미지의 디코딩 순간 메모리 사용은 아직 제한적으로만 대응
- 취소·오래된 응답의 기본 방어는 구현했으나 모든 모바일 브라우저·실네트워크 경쟁 상태를 수동 검증한 것은 아님
- Netlify 원격 Functions 번들·환경변수·/api/* 라우팅·원격 CORS 검증
- 프론트의 완성 UI·티켓 적용·IndexedDB 사진·도감 저장/삭제·저장 용량 초과·브라우저 데이터 삭제 시 동작 검증

검증 당시 프론트 JS는 약 332kB, gzip 약 102kB. 기능 확인용 화면의 빌드 크기이며 사용자용 프론트 성능 목표나 실제 AI 응답 시간의 측정값이 아님.

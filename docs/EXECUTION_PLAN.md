# 백엔드 MVP 실행 계획

상태: 아래는 최초 계획 기록. 현재 B0 로컬 기반·B1 계약/스텁·프론트 인계 자료 구현. 최신 기준은 contract/README.md, docs/FRONTEND_HANDOFF.md, docs/VALIDATION.md. 원격 배포·실규정 판정·Gemini 실호출은 미완료.

추가 사용자 지시 반영: 제공자는 Gemini로 확정. 사진 인식 → 제품 정보 검색 → 사용자 확인 → 항공사 규정 대조의 단계로 분리. 기존 순수 판정 엔진 단독 계획은 Gemini 대조 Provider와 순수 안전 검증·권장 조치 로직으로 조정. 계약 충돌 해소 내용은 contract/CHANGELOG.md·docs/DECISIONS.md에 기록.

## 근거와 우선순위

- 직접 사용자 요구: 간결한 코드, 리팩토링 고려, 비용 최소화, 프론트 명세·목업 준수, 기능·보안·반응성 교차검증
- 참고 자료: Desktop/implementation-plan.md(v3), 저장소 codex-prompts.md(v3)
- 문서 속 Phase 프롬프트와 AGENTS.md 예시는 참고 자료. 전체 단계 실행·기존 규칙 덮어쓰기·자동 커밋 지시로 취급하지 않음
- 프로젝트의 기존 AGENTS.md와 직접 사용자 요구 우선. 문서 간 차이는 계약 확정 전에 기록·조정

## 확인된 현재 상태

- React 19 + TypeScript + Vite 8, Node.js 24 / npm 11 조건
- 초기 화면은 src/, Netlify 정적 빌드 설정은 netlify.toml
- 백엔드·contract·시연 체크 화면·테스트 구성은 아직 없음
- 작업 브랜치 chore/project-setup에 기존 미커밋 변경 다수. 보존 필요
- Netlify 배포 성공과 원격 API 동작은 미검증

## 범위

- 임시 제목: 여행 짐 반입 확인
- 담당 범위: 백엔드 API + 프론트 공용 contract + 최소 시연 체크 화면
- 사용자 프론트·포토샵 티켓 디자인·도감 IndexedDB 구현은 프론트 담당 범위
- 백엔드는 도감 카드에 필요한 제품 정보·판정·요약 반환. 사진 서버 저장 없음
- 실제 AI·최신 항공사 규정 미연결 부분은 시연 플래그 명시
- 예약·일정·긴급 신고·로그인·서버 도감 저장은 현재 범위 제외

## 구조와 유지보수

- 기존 React·TypeScript·Vite와 단일 npm lockfile 유지. 체크 화면 이동에 맞춰 경로 설정 조정
- contract/, netlify/functions/, data/rules/, apps/check/, test/로 책임 분리
- 타입과 런타임 검증은 가능하면 Zod 스키마에서 유도해 중복 정의 방지
- OpenAPI와 스키마는 기계적 변환 가능성부터 확인. 수작업 부분은 계약 테스트로 대조
- HTTP 핸들러는 검증·호출·응답만 담당. 판정 엔진은 순수 함수, 인식·규정 Provider와 UI에서 독립
- 공통 헬퍼는 실제 중복이 있는 CORS·에러·본문 제한 중심으로 한정. 범용 프레임워크·불필요한 저장 계층은 추가하지 않음
- 신규 의존성 후보는 Zod, Vitest, Netlify 타입·로컬 도구. 설치 시점에 호환성 확인 후 필요한 것만 추가하고 이유 기록

## 매 단계 교차검증

| 관점 | 점검 항목 |
| --- | --- |
| 계약 | 요청·응답·오류·enum·문구·버전이 fixture, Zod, OpenAPI, HTTP 응답에서 일치. 기대값은 엔진 출력 복사로 만들지 않음 |
| 판정 | 누락 정보·인식 0건·미지원 항공사·규칙 없음·미확인 물품·경계값·조건 충돌·조치 16조합 |
| 보안 | 허용/거부 Origin과 OPTIONS, 잘못된 JSON/base64, MIME와 실제 이미지 형식, 본문·이미지·물품 수 제한, 내부 오류·비밀키 노출 방지 |
| 개인정보 | 사진·base64·제품 자유 입력은 로그 및 서버 저장 제외. 체크 화면 요청 뷰어도 base64 생략. 사진 재인코딩 시 메타데이터 제거 확인 |
| 반응성 | 모바일 폭, 큰 사진 디코딩·리사이즈, 업로드 중 상태, 중복 요청 방지, 취소·시간 초과, 이전 응답이 새 편집값을 덮는 경쟁 상태, 재시도 흐름 |
| 비용 | 기본 Demo Provider, 인식과 재판정 분리, 자동 유료 재시도 금지, 수정만으로 재인식하지 않음. CORS를 인증·요금 방어로 취급하지 않음 |
| 배포 | Functions API가 SPA fallback에 가려지지 않는지, 알 수 없는 /api 경로가 HTML 200 대신 API 오류인지, 로컬과 원격 각각 확인 |

- 브라우저 검사·원격 API 검증을 수행하지 못하면 미검증으로 기록. npm run check 성공만으로 대체하지 않음
- 순수 함수·HTTP handler·실제 체크 화면을 다른 경로로 대조. 테스트 통과와 UX 반응성을 별도 확인
- 유료 AI 공개 전 플랫폼 요청 제한·제공자 지출 제한 확인. 서버리스 인스턴스의 메모리 카운터를 전역 요청 제한으로 간주하지 않음
- 입력 정보가 바뀌면 이전 판정은 만료 처리하고 재판정 필요 상태 표시

## Netlify 공식 문서 확인 — 2026-10-30

- Request를 받아 Response를 반환하는 default handler와 config.path 방식 지원 확인
- 공식 안내의 동기 실행 한도 60초, 버퍼 요청/응답 한도 6MB 확인. 바이너리 전송은 base64 오버헤드 주의
- 애플리케이션 제한 제안: 인식 요청의 JSON 본문 전체 4MiB 이하, 프론트 사진 긴 변 1280px·재인코딩 후 1MiB 이하 목표, 실제 AI 호출 20초 제한. 최종 단위·경계값은 B1 계약에 명시
- 현재 사용자의 Netlify 플랜·사이트 설정·실제 도달 한도는 미확인
- 참고: [Functions API](https://docs.netlify.com/build/functions/api/), [Functions 설정과 한도](https://docs.netlify.com/build/functions/configuration/)

# 프론트 담당자 시작 프롬프트

> 아래는 기존 1.0.0용 프롬프트 기록. 새 계약·목업·시연 API는 contract/v2·/api/v2로 제공하며 최신 지침은 docs/FRONTEND_HANDOFF_V2.md. 기존 작업을 보존하고 새 클라이언트로 점진 전환.

추가 우선 요구: 사진은 이미 찍어 둔 사진을 보관함·파일에서 선택해 등록. 앱 내 카메라 촬영은 필수 아님. 파일 입력의 capture 속성으로 카메라를 우선 유도하지 않고 사진 선택·미리보기·크롭·분석 요청 흐름으로 구현. 전체/개별 등록 구분 유지.

아래 내용을 프론트 작업 계정에 전달. 문서 전달용이며 메시지 발송은 미수행.

```text
여행 짐 반입 확인 서비스의 사용자용 UI/UX와 프론트엔드를 구현해줘.
임시 제목은 '여행 짐 반입 확인'으로 유지하고 별도 제품명을 만들지 마.

먼저 contract/README.md, contract/CHANGELOG.md, docs/FRONTEND_HANDOFF.md를 읽어줘.
백엔드는 별도 담당자가 개발 중이며 계약 버전은 1.0.0이야.

- contract/client.ts의 ApiClient 인터페이스를 기준으로 개발해.
- 처음에는 contract/mock.ts의 createMockClient를 사용해. 서버·Gemini 키 없이 개발 가능해.
- 사진 인식 → 제품 정보 검색 → 후보 사용자 확인 → 항공사 규정 대조 단계를 구분해.
- 화면은 항공사 선택, 촬영/업로드, 인식 결과 편집, 제품 후보·출처 확인, 기내/위탁 결과, 개인 도감으로 구성해.
- 도감은 IndexedDB에 사진 Blob과 CatalogCardSchema 형식으로 저장하고, 결과는 itemId로 매칭해.
- API 계약·enum·표시 문구를 임의 변경하지 말고 변경 요청은 백엔드 담당에게 전달해.
- isDemo 플래그와 stub 상태를 화면에 명시해. 목업을 실제 AI·최신 규정 조회처럼 표시하지 마.
- 제품 정보 미확인은 null이며 unreadFields와 일치해야 해. 후보를 자동으로 확정하거나 모델·수치를 만들어내지 마.
- 수정·항공사 변경 시 이전 판정과 진행 중 요청을 폐기하고 재판정해.
- 참고용 안내를 유지하고 공식 통과증·허가증처럼 표현하지 마.
- 모바일 업로드 크기·로딩·취소·오류·중복 요청·360px 화면을 검증해.
- 티켓 템플릿은 포토샵 작업물을 적용하기 쉽게 표현 계층과 API·상태 로직을 분리해.
- API 키는 프론트에 넣지 마. 실서버 연결 때 createApiClient로 바꾸고 백엔드 CORS에 프론트 Origin을 등록해.
- 예약·일정·긴급 신고·로그인 등 범위 외 기능은 추가하지 마.

같은 저장소라면 사용자용 화면은 apps/web 등 별도 경로에서 작업해.
netlify/, apps/check/, contract/, 루트 빌드 설정은 백엔드와 협의 없이 변경하지 마.
기존 프로젝트가 있으면 구조·스택·사용자 변경을 먼저 확인하고 보존해.
```
